# 从客户端 Git 导出固定地图

`make map` 直接拉取客户端 Git 指定版本的地图文件，校验后转成服务端 Lua。后端不随机生成、不重排资源、不修改坐标，也不维护另一份地图模板。

## 使用

默认客户端仓库和分支在后端 Makefile：

```make
CLIENT_REPO ?= git@github.com:literwave/slg_game_client.git
CLIENT_REF ?= master
```

在后端仓库根目录运行：

```sh
make map                                # 拉取 master 当前提交并导出
make map CLIENT_REF=<提交号或标签>        # 导出指定版本
make map-check                          # 按包内记录的原提交重新拉取核对
make map-check-server                    # 比较 res/map 与 Git 中指定版本
make map-test                           # 运行离线工具与版本绑定测试
```

也可以通过 `CLIENT_REPO=其他客户端Git地址` 覆盖仓库。需要当前系统具有该仓库的 Git 读取权限。依赖 Python 3.10+、Git、Lua 5.4、GNU Make、sha256sum，不启动 Cocos 或 Skynet，不连接数据库。

旧 `SEED`、`PROFILE`、`CLIENT` 和 `--seed` 用法已禁用。工具不读取本地客户端工作区作为替代；拉取失败就报错，不偷偷使用缓存或旧副本。

## 数据流程

1. 拉取指定分支、标签或提交，并立即解析为固定提交号。
2. 只读取所需的地图文件对象；不下载全部美术，不改客户端工作区，不提交或推送代码。
3. JSON 的每一格原样转换为 Lua，保留零起始 `cellId = y * width + x`。
4. 验证资源、城池、关口、山河、空地、城市占地与实际 TMX 一致，检查两端资源类型与等级配置。
5. 输出文件哈希、客户端仓库地址和提交号，再发布完整候选包。

来源文件：

- `assets/resources/config/mapRes_0.json`
- `assets/resources/world/campaign-map.json`
- `assets/resources/world/original-landscape.json`
- `assets/resources/world/map.tmx`
- `tools/world/fixed-birth-resources.json`
- `tools/world/fixed-inner-resources.json`
- 客户端 `ResLandType.json`、`ResLand.json`，仅用于协议兼容性检查

服务端配置继续使用 `game_common/server/res/ResLandType.lua`、`ResLand.lua`，不随地图包复制。

地图包中的客户端文件保持 Git 原始字节。服务端 Lua 与这些文件逐项对应，地图差异必须为 0。城池未提供 ID 时只为校验计算索引，不会给源数据补字段。

兼容已经提交的 v1 地图与新 v2 地图。v1 保留原有圆环州域和历史 spawnZones 字段作为源数据，后端不使用这些提示分配玩家出生；v2 按 regionRows 校验州域并验证关口关闭后的八方向隔离。两种版本都不重新生成地形。

## 结果

输出目录：`build/maps/<mapRevision>/`。

- `server/`：`mapRes_0.lua`、`campaign-map.lua`、`terrain.lua`、`manifest.lua`
- `client/`：Git 中的地图原文件，以及包版本/客户端提交号标记
- `inputs/`：固定点原文件与校验约束
- `manifest.json`：文件摘要、客户端 Git 提交及导出工具摘要
- `report.json`、`diff.json`：校验报告，与来源地图的格子差异为 0
- `preview.html`、`preview.png`、`resources.png`：布局与资源分布技术预览
- `map-package.zip`：固定文件顺序和时间戳的交付包

同样提交与工具/配置重复导出会校验并复用相同版本。`map-check` 始终使用包内记录的提交，不会因 master 前进而改查另一张地图。

```sh
make map-check MAP=<地图版本号>
make map-check-server CLIENT_REF=<客户端提交号> SERVER_MAP=build/maps/<地图版本号>/server
make map-diff FROM=<旧固定地图版本> TO=<新固定地图版本>
```

`map-check-server` 直接读取指定目录的服务端 Lua，逐格比较资源类型与等级，并比较空地、山河阻挡、城池、州域和关口。不同则返回非零状态。这检查的是磁盘数据，不代表运行中的进程已加载新地图。

## 版本使用

客户端与服务端应使用同一客户端提交。当前预览如果包含未提交或未推送的地图修改，远端 Git 不会包含它们；先确认、提交并推送地图，再运行 `make map`。本工具不会代替开发者提交整个客户端工作区，也不自动修改当前预览。

`latest.json` 只记录最后成功导出的候选包，服务端不会自动跟随它。为新世界配置固定版本：

```lua
map_package_root = "../build/maps" -- 相对 skynet 工作目录，可配置为持久目录
map_revision = "导出得到的完整地图版本号"
```

现有世界默认仍读 `res/map/`。启动时验证文件哈希和当前数据库的地图版本绑定；已有存档不能直接换另一张地图。升级前已有玩家的世界先绑定 `config/map_legacy.lua` 中的原地图。版本绑定用于防止城池、占领和行军数据与新地图错位，工具不清库、不热切换世界。

当前没有新增客户端登录版本握手，包内版本标记也不会自动写回客户端；发布时通过提交号及逐格核对保证使用同一份地图。
